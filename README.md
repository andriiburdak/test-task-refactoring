# Тестове завдання: TesterResults

## Контекст

На виробничій лінії стоять кілька тестерів друкованих плат (PCB). Кожен тестер пише лог своїх прогонів: одна плата - один рядок із серійним номером, результатом (PASS/FAIL), кодом помилки і часом циклу. Плата, яка не пройшла тест, зазвичай йде на повторний прогін (retest).

`TesterResults` - невеликий консольний застосунок на .NET 8, який читає ці логи з папки `data/`, рахує статистику по кожному тестеру і загальний показник **PRT (pass on retest)** - частку плат, які після FAIL пройшли тест повторно, - а потім "відправляє" звіт у MES (відправка в цьому завданні лише імітується виводом у консоль).

Формат рядка логу:

```
timestamp;serialNumber;result;errorCode;cycleTimeSeconds
2026-09-30T08:00:43;SN001001;FAIL;17;31.8
```

Рядки, що починаються з `#`, - коментарі.

## Що треба зробити

Застосунок написаний поспіхом і працює неправильно. Ваше завдання - привести його до стану, в якому його можна віддати на виробництво.

1. **Запустіть застосунок і розберіться, що він робить** (`dotnet run --project src/TesterResults`).
2. **Знайдіть і виправте проблеми в коді.** Їх кілька, різного типу: від тих, що ламають запуск, до тих, що дають неправильні цифри або є неприйнятними для виробничого коду. Дані в `data/` вважайте правильними: кілька рядків там навмисно пошкоджені - це реальна ситуація, і застосунок має обробляти її коректно, а не мовчки.
3. **Додайте функціональність:**
   - шлях до папки з логами і шлях до файлу звіту передаються аргументами командного рядка (зараз шлях до `data/` захардкоджений);
   - підсумкова таблиця по тестерах експортується у CSV-файл (колонки: тестер, всього, pass, fail, pass on retest, середній час циклу).
4. **Оформіть результат так, як ви оформили б зміну в реальному проекті:**
   - окрема гілка, осмислені коміти;
   - Pull Request з описом: які проблеми знайшли, чому це проблеми і як виправили;
   - оновлений README (як запускати з новими аргументами).

Тести на виправлену логіку - плюс, але не обов'язкові.

## Умови

- Орієнтовний обсяг - **близько 4 годин**.
- Потрібен .NET SDK 8 або новіший (Windows, Linux або macOS); IDE - будь-яка.
- .NET 8, без Docker, без бази даних, без зовнішніх сервісів. Нові NuGet-пакети - тільки якщо справді потрібні, з поясненням.

- Чи знайдені проблеми і чи правильно зрозуміла їхня причина (а не тільки симптом).
- Якість виправлень: чи не з'явились нові проблеми, чи код став простішим і зрозумілішим.

## Структура

```
src/TesterResults/          застосунок
  Parsing/LogParser.cs      читання логів
  Processing/StatsAggregator.cs   підрахунок статистики
  Reporting/ReportWriter.cs       вивід звіту
  Reporting/ReportUploader.cs     відправка в MES (імітація)
tests/TesterResults.Tests/  unit-тести (xunit)
data/                       логи тестерів
```

```
dotnet build
dotnet test
dotnet run --project src/TesterResults
```
